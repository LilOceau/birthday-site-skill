# 清理与回滚

## 保留边界

必须保留当前完整 dist、未提交修改、Git 历史、导入/转换/验证脚本、配置、素材清单与原始照片/视频。README 和 OPENING-NOTES 中有历史决策，不能因包含过时描述就删除。浏览器个人进度与账号认证目录不属于构建缓存。

`.tools` 混合存放工具、审核材料和缓存：`imageio_ffmpeg` 是导入依赖，`pw-browsers` 可能是唯一浏览器运行时，`npm-cache/_npx` 可能是已安装的 Netlify CLI。不能因为目录名包含 cache 或 tools 就整体删除。无法读取的目录列为保留/待检查，不当作空目录。

## 操作流程

1. 盘点路径、实际大小、Git 状态、部署记录与调用关系。对需要保护的当前发布文件和原素材保存 SHA256 清单。
2. 保存包含未跟踪资源的当前完整源码与 dist 快照；可另用 `git bundle create <路径> --all` 保存提交历史。仅 Git bundle 不含工作区未提交内容。
3. 完整读取新压缩包并核对文件清单与哈希，验证 bundle。回滚说明写清各包包含的是可部署 dist、完整工程，还是仅媒体转换备份。
4. 对 `.publish-v*` 等中间目录逐文件比较对应压缩包。完全相同才可将目录视为冗余；目录内独有的清单、脚本、报告单独保留。最新发布 staging 可能与当前工程不同，先核对线上。
5. 历史压缩包优先保留当前快照、最近生产基线、重大内容/交互里程碑、画质转换前版本及无法从其他已验证存储恢复的版本。较旧包仅在证明其全部内容可恢复时删除；名称相近或文件大小相近不是重复证据。
6. 清理可再生 `__pycache__`、过期调试日志、经过确认的下载缓存与重复打包目录。小型测试结果/关键截图通常值得保留作为回归证据；一次性大测试副本可在验证独有文件已保存后清理。先写清单，再按精确路径操作，拒绝符号链接/重解析点和超出工作区的目标。
7. 重新核对当前 dist 和原素材哈希，运行基础回归，报告实际删除项、释放大小、保留项、恢复方法和受阻项。

## 恢复

先在新目录中展开所选完整快照，核对其哈希；必要时从 bundle 克隆历史，再把含未提交内容的快照叠到独立副本。保持原工程不动。日期导入还需要外部原始素材与 FFmpeg；仅浏览/部署完整 dist 不需要它们。确认预览与用户选择的回滚目标后，才按实际发布授权更新正式站。
